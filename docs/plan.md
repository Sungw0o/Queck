### 1. 원본 자료와 지식 위키 구분
- 배경: 지금은 사용자가 쓴 메모와 AI가 종합한 지식을 구분하거나 근거 원본을 추적할 수 없다.
- 범위: 원본 자료·지식 문서를 구분하고 출처 URL·수집 시점·원문을 보존한다. 첫 범위는 텍스트·마크다운 입력이며 URL은 출처로 기록한다. 원본을 AI 정리 결과로 덮어쓰지 않는다.
- 완료 조건: 자료 한 건을 등록하고 원본을 그대로 읽을 수 있다. 그 자료에서 만든 지식 페이지에서 어떤 원본을 사용했는지 이동해 확인한다.

### 2. 에이전트의 위키 정리·인수인계 절차
- 배경: 현재 MCP에는 읽기·쓰기 도구만 있고 자료를 지식으로 축적하는 일관된 작업 절차가 없다.
- 범위: 원본 읽기 → 기존 관련 문서 검색 → 요약·주제별 페이지 생성 또는 갱신 → 출처·관련 문서·색인·변경 기록 갱신의 절차와 필요한 MCP 지원을 마련한다. 서로 다른 주장과 미확인 내용을 구분하고, 자료 하나씩 순서대로 처리한다. 기존 생성·수정 승인 정책을 유지한다.
- 완료 조건: 자료 두 건을 차례대로 처리해 중복 페이지 대신 기존 주제 문서가 갱신되고, 어떤 자료가 어떤 변경을 만들었는지 확인한다. 중간 실패를 완료로 기록하지 않는다.

### 3. 문서 연결과 위키 점검
- 배경: 페이지 계층만으로는 주제 간 연결, 근거가 빠진 문장, 오래된 결론을 찾기 어렵다.
- 범위: 위키 문서 간 링크·역방향 연결과 색인 탐색을 지원한다. 에이전트가 출처 누락·깨진 링크·상충하는 내용·새 자료 이후 확인이 필요한 문서를 점검하고 결과를 기록하는 절차를 둔다.
- 완료 조건: 한 문서를 참조하는 다른 문서를 찾을 수 있다. 의도적으로 만든 출처 누락·깨진 링크가 점검 결과에 드러난다.

### 4. RAG 발췌 개선과 품질 기준
- 배경: 현재 검색은 키워드와 본문 앞 300자에 의존해 긴 문서의 근거를 보여 주지 못한다.
- 범위: M4의 검색어 주변 발췌를 우선 적용하고 제목·문서 종류·근거 위치·원문 링크를 함께 반환한다. 실제 자료와 대표 질문 세트로 원문 찾기·출처 정확성·근거 없는 답변 여부를 비교한다. 의미 검색은 기존 M3 시작 조건을 충족할 때만 별도로 진행한다.
- 완료 조건: 문서 뒤쪽 근거도 결과에 나타나고 위키의 결론을 원본까지 추적한다. 같은 질문 세트의 검색 결과를 개선 전후로 비교할 수 있다.

진행 순서: M4 동시 수정 충돌 감지 → 원본/지식 구분 → 위키 정리 절차 → 검색 발췌·품질 검사 → 연결·점검. PDF 추출·웹 본문 자동 수집·임베딩은 첫 버전에 넣지 않고 실제 자료와 검색 실패를 보고 범위를 정한다.
