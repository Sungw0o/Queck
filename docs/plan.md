## M2. 지라 ↔ 위키 연결
### 이슈 편집 초안 유실 방지
- [x] 완료 (`f86cb18`). 저장 실패·중복 요청·취소/반환·미저장 이동·네트워크 오류 회귀 검사와 재빌드·REST/MCP/RAG 스모크 통과. 실제 취소 확인창 표시 확인. 확인창 거부 후 보존은 자동 검사로 검증(브라우저 도구가 확인창 처리에서 중단됨). 테스트 데이터 삭제 완료.
- 배경: 이슈 저장 실패 시 창이 먼저 닫히고, 취소·Esc·새로고침에서 사람용 요약과 에이전트 문서를 확인 없이 잃을 수 있다.
- 범위: 저장 성공 후 창을 닫고 실패 시 두 초안을 유지한다. 저장 중 중복 요청과 편집·창 닫기를 막는다. 변경이 있을 때 취소·Esc·새로고침·해시 이동에서 확인한다. 회귀 검사를 CI에서 실행한다.
- 완료 조건: 저장 실패 후 재시도할 수 있고, 변경 취소를 거부하면 두 문서가 보존된다. 변경하지 않은 창은 확인 없이 닫힌다.

### 문서 본문의 `QK-12`를 이슈 링크로
- 배경: 위키에서 이슈를 언급해도 이동할 수 없다.
- 범위: 렌더링된 문서에서 `QK-숫자`를 `#issue/숫자` 링크로 바꾼다. 코드 블록 안은 건드리지 않는다. DOMPurify 정화 이후에 처리한다.
- [x] 완료 (`77313b0`, 검증 기록: `f86cb18`). 실제 문서 본문의 QK 링크 클릭으로 해당 이슈 창이 열리는 것을 확인했다. 인라인 코드·코드 블록·기존 링크는 변경되지 않는 것도 확인했다.
- 완료 조건: 문서의 `QK-3`을 누르면 보드에서 QK-3 다이얼로그가 열린다.

### 이슈 설명 마크다운 미리보기
- 배경: 이슈 설명은 마크다운으로 저장되지만 다이얼로그에서는 원문만 보인다.
- 범위: 다이얼로그에 미리보기 전환 버튼을 둔다. 렌더링은 문서와 같은 `DOMPurify.sanitize(marked.parse())`를 쓴다.
- 진행: 코드 구현 및 `node scripts/issue-preview.test.mjs` 상태 전환 검사 완료. 재빌드·스모크·라이트 화면의 목록/코드 미리보기·정화 처리 확인. 다크 화면 검증은 대기 중이다.
- 완료 조건: 미리보기에서 목록, 코드, 링크가 문서와 같은 모양으로 보인다.

## M3. AI 연결
### 이슈의 사람용 요약·에이전트 문서 분리와 MCP RAG
- [x] 구현 완료 (`c3a2b4e`). 백업 후 기존 DB 컬럼 추가. 재빌드·REST/MCP 두 문서 독립 저장/검색/조회/수정·출처 링크·미리보기 정화·라이트 화면 검증 통과. 테스트 데이터 삭제 완료. 다크 화면 육안 검증은 남음.
- 배경: 짧은 이슈 설명과 에이전트 간 인수인계 기록이 섞이면 읽기와 검색이 어렵다.
- 범위: 기존 설명은 사람용으로 보존하고 에이전트 문서를 별도로 저장·편집·미리보기한다. REST/MCP 생성·수정·조회 및 키워드 검색에 두 문서를 포함하고 검색 출처를 구분한다. 기존 DB는 백업 후 컬럼을 추가한다.
- 완료 조건: 사람용 내용을 바꾸지 않고 에이전트 문서만 수정할 수 있다. 에이전트 문서에만 있는 한글 키워드로 검색해 원문과 이슈 출처를 조회할 수 있다. 앱 안에 LLM 호출은 추가하지 않는다.

### Claude Desktop MCP 연결
- 배경: 지금은 이 폴더에서 연 Claude Code만 Quack을 검색할 수 있다.
- 범위: `scripts/mcp-bridge.mjs`(stdio 중계)를 Claude Desktop 설정에 등록하고, 그 방법을 README에 적는다.
- 진행: 중계 스크립트, 등록 스크립트(`quack desktop`), 스모크 검사까지 끝. 이 PC에서 Desktop을 끈 상태로 등록하고, 실제로 답이 나오는지는 아직 확인 전.
- 완료 조건: Claude Desktop에서 "Quack에서 ○○ 찾아줘"라고 하면 출처가 달린 답이 나온다.

### (조건부) pgvector 의미 검색
- 시작 조건: 키워드 검색이 실제로 자주 빗나갈 때만 한다. 그 전에는 하지 않는다.
- 범위: `quack backup` → DB 이미지 교체 → 복원 → 임베딩 컬럼과 검색. 임베딩은 앱 밖이나 로컬 모델로 만든다(앱에 API 키 금지).
- 완료 조건: 같은 질문 세트에서 키워드 검색보다 맞는 문서를 더 많이 찾는다.

## M4. 다음 개발 후보
### 같은 문서의 동시 수정 충돌 감지
- 배경: 사람이거나 여러 에이전트가 같은 문서를 수정하면 마지막 저장이 앞선 내용을 덮어쓴다.
- 범위: 오래된 원문에 기반한 저장을 감지하고 덮어쓰지 않는다. 충돌 시 현재 초안과 서버의 최신 내용을 확인할 수 있게 한다. REST/MCP에서 충돌을 명확히 알려 준다.
- 완료 조건: 두 편집자가 같은 문서를 연 뒤 순서대로 저장하면 뒤의 오래된 저장은 거부되고 앞서 저장한 내용과 뒤의 초안 모두 보존된다.

### 검색 결과에서 일치한 부분을 발췌
- 배경: 현재 본문 앞 300자만 보여 주므로 긴 에이전트 문서의 뒤쪽에서 찾은 근거가 검색 결과에 보이지 않는다.
- 범위: 일치한 검색어 주변의 본문을 보여 준다. 사람용·에이전트 문서 출처 구분과 원문 링크를 유지한다. 키워드 검색 방식을 유지한다.
- 완료 조건: 300자 뒤에만 존재하는 키워드도 결과 발췌에 나타나고 MCP에서 원문을 읽어 근거를 확인할 수 있다.
